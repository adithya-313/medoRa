## Context

Phase 0 froze and audited v1 (prv3 tag v1-final). What it found, from the checked artifacts:

- Features: 64 in total: 12 working, 5 mocked, 5 broken, 3 missing, 39 untested. 5 security findings are recorded.
- Tests (docker-with-db baseline): 198 passed, 29 failed, 6 errors, 0 skipped. The health_risk suite adds 51 passed.
- Vendor scorecard: 8 designed flaw tests fail on v1 as intended; 1 positive control passes.
- Data: 34 items audited; 0 allowed for production, 1 test-fixture-only, 17 not-for-production, 16 to discard.
- Screens: 8 pages; 22 actions to keep, 5 to rebuild properly; 10 frontend calls reach no screen; 8 hard-coded items in the UI.

Given owner decisions (stated as given, not re-argued here):

- v2 gets a new UI design; v1's look is not carried over. (2026-10-20/21)
- Drug interactions are reference information only (possible SaMD). (2026-10-20/21)
- Tauri v2 is the desktop shell. (2026-10-20/21)
- v1's 254k-row product CSV is a test fixture only. (2026-10-20/21)
- Prescription reading and the Malayalam voice assistant move to v3 (neither exists in v1, so no v1 item is deferred). (2026-10-20/21)
- Planned drops in the owner's plan: the Kafka producer with Redpanda, the SGWA service with the federated API, and the compute hypervisor. (2026-10-20/21)
- Clinical safety judge: rebuild as warn-only (the pharmacist confirms with a reason, which is logged); no hard checkout lock; Phase 6. (2026-10-22)
- Every other item that was listed as 'Owner to confirm': the proposed choice is accepted. (2026-10-22)

## Decision

Meaning: **keep** = v2 carries the behaviour and the tests that prove it (only for working features); **rebuild** = v2 builds it again, test-first, in the stated phase; **drop** = v2 does not have it; **defer-v3** = postponed by the owner.

Identity and tenancy come first (3 - Identity, roles, three-app permissions) because 4 features carry 5 security findings:

- inventory-stock-projection: No tenant filter: the stock total sums the SKU's batches across all tenants
- inventory-triage: No tenant filter: loads every tenant's batches and returns their value and expiry totals
- supplier-scorecard: No tenant filter: the scorecard mixes every shop's orders for a supplier (flaw F4)
- ui-authentication: A missing X-Tenant-ID header becomes system_admin, the all-tenants view; The tenant is a constant the browser sends; no sign-in proves who the user is

50 items are dropped, so v2 starts without the Kafka event mesh, federated aggregation, the compute hypervisor, the CUDA package stack and the generated files and logs listed above.

## Alternatives considered

1. **Rewrite v1 in place.** Evidence against: only 12 of 64 features are proven working, 39 have no test, 5 are mocked and 3 are missing; the baseline suite has 29 failures and 6 errors; the vendor scorecard has 8 proven flaws; and v1's requirements do not install on Windows. An in-place rewrite would have to fix, test and re-secure almost everything while keeping a fragile base running.

2. **Fresh repo (chosen).** v2 starts empty. v1 stays frozen and read-only as a reference. The checked Phase 0 artifacts decide what v2 carries over: working behaviour and its tests are kept as the specification, everything else is rebuilt test-first or dropped, so nothing is copied across unexamined.

## Why no benchmark

This ADR is a scope decision (what to carry over), not a technology choice, so there is nothing to benchmark. The benchmark-before-choosing rule applies from ADR-001 onward.
